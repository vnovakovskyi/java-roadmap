# Packaging and Running (Jar and Container Image)

> [!info] Topic
> **Area:** Project · **Module:** 10 · **Priority:** good · **Est:** 3h
> **Why this matters:** Shipping means producing something that runs anywhere. An executable jar and
> a container image are how Java services are delivered today — and `docker compose up` running your
> whole app is a great finish for a portfolio project.

## Learning Objectives
- Build and run an executable Spring Boot jar.
- Containerize the app with a Dockerfile or Buildpacks.
- Run the app and its database together with Docker Compose.

## Learn
- [ ] Do: the [Spring Boot with Docker guide](https://spring.io/guides/gs/spring-boot-docker/).
- [ ] Read:
      [Spring Boot — Container Images](https://docs.spring.io/spring-boot/reference/packaging/container-images/index.html)
      and the Maven plugin's
      [build-image goal](https://docs.spring.io/spring-boot/maven-plugin/build-image.html).

## Concepts
- [ ] Spring Boot builds a self-contained executable jar: `./mvnw package` (or `./gradlew bootJar`),
      run with `java -jar target/app.jar`.
- [ ] A **Dockerfile** describes an image: a JRE base image, copy the jar, set the entrypoint. Or
      skip the Dockerfile: `./mvnw spring-boot:build-image` builds an optimized image with Cloud
      Native Buildpacks.
- [ ] Pass config and secrets as environment variables at run time — never bake them into the image.
- [ ] Extend `compose.yaml` with an `app` service that depends on the database, so
      `docker compose up` runs everything.
- [ ] Keep images small (JRE, not JDK; layered jars). Deeper hardening is beyond junior scope.

```dockerfile
FROM eclipse-temurin:25-jre
WORKDIR /app
COPY target/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

## Practice
**Goal:** Run your app as an artifact and as a container.
**Steps:**
- [ ] Build the jar and run it with `java -jar`; hit an endpoint.
- [ ] Build an image with the Dockerfile above, then with `spring-boot:build-image`; compare.
- [ ] Add the app to `compose.yaml` with its database settings from environment variables and run
      the whole stack.

## Self-check
Answer out loud or on paper first, then expand to compare.

> [!question]- What makes a Spring Boot jar "executable"?
> It contains your code, all dependency jars, and a launcher, so `java -jar` starts the whole
> application with an embedded server.

> [!question]- Why use a JRE base image instead of a JDK?
> The app only needs to run, not compile; a JRE image is smaller and has fewer tools an attacker
> could misuse.

> [!question]- How do you pass the database password to the container?
> As an environment variable at run time (`-e` or the `environment:` section in Compose, ideally
> from a secret store) — never inside the image.
