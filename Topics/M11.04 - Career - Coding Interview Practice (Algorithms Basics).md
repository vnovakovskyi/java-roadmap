# Coding Interview Practice (Algorithms Basics)

> [!info] Topic
> **Area:** Career · **Module:** 11 · **Priority:** good · **Est:** 10h
> **Why this matters:** Many companies include a coding exercise, even for juniors. It's a learnable
> skill: a dozen patterns cover most problems. Practice steadily alongside your projects instead of
> cramming.

## Learning Objectives
- Recognize the common problem patterns.
- Solve easy and some medium problems in Java with the right data structures.
- Explain the time and space complexity of your solution.

## Learn
- [ ] Follow: [NeetCode Roadmap](https://neetcode.io/roadmap) or the
      [LeetCode 75](https://leetcode.com/studyplan/leetcode-75/) study plan.
- [ ] Read:
      [Tech Interview Handbook — Coding Interview Prep](https://www.techinterviewhandbook.org/coding-interview-prep/)
      and the
      [algorithms study cheatsheet](https://www.techinterviewhandbook.org/algorithms/study-cheatsheet/).
- [ ] Revisit [[M4.03 - Java APIs - Choosing Collections and Big-O Basics]] and
      [[M2.07 - Core Java - Recursion]].

## Concepts
- [ ] Patterns over problems: hashing (counting and lookups), two pointers, sliding window, stack,
      binary search, BFS/DFS on trees and graphs, sorting, simple recursion.
- [ ] Java toolbox: `HashMap`, `HashSet`, `ArrayDeque`, `PriorityQueue`, `Arrays.sort`,
      `StringBuilder`, `Collections`.
- [ ] Sorting: know quicksort and merge sort by idea (both O(n log n) on average) and why insertion
      sort (O(n²)) is still fast on nearly sorted data. Java's `Arrays.sort` uses dual-pivot
      quicksort for primitives and stable TimSort for objects (`List.sort` too).
- [ ] Always state complexity: e.g. "O(n) time, O(n) extra space".
- [ ] Method: understand → examples and edge cases → brute force → optimize → code → test by hand.
- [ ] Time-box each problem (30–45 minutes); then study a solution and solve it again yourself two
      days later.
- [ ] Balance: for many junior roles projects matter more than hard puzzles — don't let LeetCode
      replace building.

## Practice
**Goal:** Build pattern fluency.
**Steps:**
- [ ] Solve 20 easy problems, grouped by pattern; write each solution's complexity in a comment.
- [ ] Solve 5 medium problems.
- [ ] Re-solve 5 problems from memory a week later.
- [ ] Do one timed mock: 45 minutes, think out loud, test your own code.

## Self-check
Answer out loud or on paper first, then expand to compare.

> [!question]- How do you find two numbers in an array that sum to a target in O(n)?
> Walk the array once, storing each value's index in a `HashMap`; for each number, check whether
> `target - number` is already in the map.

> [!question]- When does the two-pointer technique apply?
> On sorted arrays or strings when you compare or combine elements from both ends (or two positions
> moving forward), e.g. pair sums, palindromes, merging.

> [!question]- Quicksort vs merge sort?
> Both average O(n log n). Merge sort guarantees O(n log n) and is stable but needs O(n) extra
> memory; quicksort sorts in place and is usually faster, but its worst case is O(n²).

> [!question]- BFS vs DFS — when would you choose BFS?
> When you need the shortest path or the fewest steps in an unweighted graph or grid: BFS explores
> level by level.

## Definition of Done
- [ ] I've solved 20+ easy and 5+ medium problems.
- [ ] I can name the pattern behind a problem and its complexity.
- [ ] I completed a timed mock while thinking out loud.
- [ ] I can answer the Self-check questions without peeking.
