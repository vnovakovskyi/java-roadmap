# equals, hashCode and toString

> [!info] Topic
> **Area:** OOP · **Module:** 3 · **Priority:** must · **Est:** 3h
> **Why this matters:** These three `Object` methods control equality, hashing, and debugging
> output. Getting `equals`/`hashCode` wrong silently breaks `HashMap`/`HashSet` — a very common real
> bug.

## Learning Objectives
- Override `equals`, `hashCode`, and `toString` correctly.
- Explain the equals/hashCode contract.
- Know when to let the IDE or records generate them.

## Learn
- [ ] Read:
      [dev.java — Object as a Superclass](https://dev.java/learn/language/oop/inheritance/objects/)
      (the `equals`/`hashCode` part).
- [ ] Reference: the
      [`Object` Javadoc](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/Object.html)
      for `equals`, `hashCode`, `toString`.
- [ ] Optional: *Effective Java*, items 10–12.

## Concepts
- [ ] `==` compares references; `equals` compares **logical equality** (you define what that means).
- [ ] **Contract:** if `a.equals(b)` then `a.hashCode() == b.hashCode()`. Break it and hash-based
      collections misbehave.
- [ ] Override both together, using the same fields; `Objects.equals` and `Objects.hash` help.
- [ ] `toString` returns a readable representation — invaluable in logs and the debugger.
- [ ] **Records** (Module 5) generate all three; the IDE can generate them for normal classes.

## Practice
**Goal:** Make value objects behave correctly in collections.
**Steps:**
- [ ] Write a `Point(x, y)` class; override `equals`, `hashCode`, `toString`.
- [ ] Put points in a `HashSet` (`var set = new HashSet<Point>(); set.add(...)` — collections come
      next module); add a duplicate `(1,1)` and confirm the set keeps one.
- [ ] Delete `hashCode` (keep `equals`) and watch the set accept a "duplicate"; then restore it.

## Self-check
Answer out loud or on paper first, then expand to compare.

> [!question]- State the equals/hashCode contract.
> Equal objects must have equal hash codes. (Unequal objects may share a hash code — that's allowed,
> just slower.)

> [!question]- You override `equals` but not `hashCode`. What breaks?
> Hash-based collections put "equal" objects in different buckets, so `HashSet` keeps duplicates and
> `HashMap.get` fails to find keys.

> [!question]- Is `public int hashCode() { return 42; }` legal?
> Legal — the contract holds — but every object lands in the same bucket, so lookups degrade from
> fast to linear.

> [!question]- Why override `toString`?
> So logs, error messages, and the debugger show meaningful values instead of `Point@1b6d3586`.
