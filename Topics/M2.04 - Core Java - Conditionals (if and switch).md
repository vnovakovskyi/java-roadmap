# Conditionals (if and switch)

> [!info] Topic
> **Area:** Core Java · **Module:** 2 · **Priority:** must · **Est:** 3h
> **Why this matters:** Programs make decisions. `if`/`else` and `switch` are how your code branches
> — the basis of all logic.

## Learning Objectives
- Write `if` / `else if` / `else` chains and nested conditions.
- Use the ternary operator for simple choices.
- Use modern `switch` expressions.

## Learn
- [ ] Read:
      [dev.java — Control Flow Statements](https://dev.java/learn/language/constructs/basics/controlling-flow/)
      (the `if` parts).
- [ ] Read:
      [dev.java — Branching with Switch Expressions](https://dev.java/learn/language/constructs/basics/switch-expression/).
- [ ] Skim:
      [dev.java — Branching with Switch Statements](https://dev.java/learn/language/constructs/basics/switch-statement/)
      — the old form you'll still meet in existing code.

## Concepts
- [ ] `if (condition) { ... } else { ... }`; conditions must be `boolean`.
- [ ] Chain with `else if`; avoid deep nesting by returning early or combining conditions.
- [ ] Ternary: `result = cond ? a : b` for compact either/or.
- [ ] Modern `switch`: `case X -> ...` (no fall-through), several labels per case (`case 6, 7 ->`),
      and it can be an **expression** that returns a value; use `yield` inside a block.
- [ ] `switch` works on `int`, `String`, `enum`, and more (patterns in Module 5); the old `case X:`
      + `break` form falls through if you forget `break`.

## Practice
**Goal:** Branch on real input.
**Steps:**
- [ ] Write a grade classifier: a score → letter grade using `if/else if`.
- [ ] Rewrite part of it with a `switch` expression (e.g. letter → description).
- [ ] Use a ternary to print "even"/"odd" for a number.
- [ ] Write an old-style `switch` without `break` and watch it fall through; then convert it to
      arrow form.

## Self-check
Answer out loud or on paper first, then expand to compare.

> [!question]- What's wrong with `if (x = 5)`?
> It's an assignment, not a comparison. In Java it doesn't even compile, because the condition must
> be a `boolean`. Use `==`.

> [!question]- What happens in an old-style `switch` if you forget `break`?
> Execution falls through into the following cases until it hits a `break` or the end. The arrow
> form (`->`) never falls through.

> [!question]- Write a switch expression that maps a day number to "weekend" or "weekday".
> `String kind = switch (day) { case 6, 7 -> "weekend"; default -> "weekday"; };`

> [!question]- When does a ternary hurt readability?
> When it's nested, long, or has side effects — then a plain `if/else` is clearer.
