# AI Coding Assistants in Your Workflow

> [!info] Topic
> **Area:** Tooling · **Module:** 6 · **Priority:** good · **Est:** 2h
> **Why this matters:** Most teams now code with an AI assistant in the IDE — completions, chat, and
> agents that edit several files at once. Employers expect you to use them productively *and*
> safely: AI multiplies a developer who can judge its output and misleads one who can't.

## Learning Objectives
- Use completion, chat, and agent features for real tasks.
- Review AI-generated code the way you'd review a colleague's pull request.
- Follow privacy, security, and licensing rules.

## Learn
- [ ] Read: the getting-started pages of your assistant —
      [JetBrains AI Assistant](https://www.jetbrains.com/help/ai-assistant/) or
      [GitHub Copilot](https://docs.github.com/en/copilot).
- [ ] Revisit [[M1.07 - Foundations - Getting Unstuck and Learning with AI]] — those learning rules
      still apply to every Practice task.

## Concepts
- [ ] Three modes: **inline completion** (finishes what you're typing), **chat** (explain, propose,
      refactor), **agents** (plan and edit many files, run commands). More autonomy means more
      output to review.
- [ ] **You own every line you commit.** Read, understand, and test AI output before accepting it;
      if you can't explain it, don't merge it.
- [ ] Better answers come from context: the relevant files, your versions (Java 25, Spring Boot 4),
      the exact error, and small, specific requests.
- [ ] Typical failure modes: outdated APIs, invented methods or libraries (check that a dependency
      really exists on Maven Central), missing edge cases, security holes (string-concatenated SQL,
      disabled validation), and tests that only restate the implementation.
- [ ] Tests are your safety net: keep them green, and write or at least scrutinize the important
      ones yourself.
- [ ] Company rules come first: many employers restrict which tools may see their code. Never paste
      secrets.

## Practice
**Goal:** Use an assistant on real code — and catch it being wrong.
**Steps:**
- [ ] Ask the assistant to explain an unfamiliar codebase, such as
      [Spring PetClinic](https://github.com/spring-projects/spring-petclinic): where does a request
      go? Verify by reading the code.
- [ ] Ask it to generate unit tests for a class you wrote; delete the tests that don't check real
      behavior and add the ones it missed.
- [ ] Ask for a refactoring of your Bookshelf code and review the diff like a pull request — accept
      only what you understand.
- [ ] Ask about a Spring Boot 4 change (e.g. how to mock a bean in a test) and check the answer
      against the official docs.

## Self-check
Answer out loud or on paper first, then expand to compare.

> [!question]- AI-generated code compiles and the tests pass. Are you done?
> No — you still have to read and understand it: edge cases, error handling, security, naming, and
> whether the tests check behavior or just mirror the code.

> [!question]- Name three typical mistakes of AI coding assistants.
> Outdated APIs or versions, invented methods or dependencies, and subtle bugs or security holes
> (missing validation, SQL built from strings, unhandled edge cases).

> [!question]- What context makes an assistant's answer better?
> The relevant code, the exact versions you use, the full error message, what you already tried, and
> a small, specific question.

## Definition of Done
- [ ] I use AI completion and chat in my IDE for real tasks.
- [ ] I review AI output critically and caught at least one wrong suggestion.
- [ ] I know the privacy and security rules for using AI tools.
- [ ] I can answer the Self-check questions without peeking.
