# The Job Search

> [!info] Topic
> **Area:** Career · **Module:** 11 · **Priority:** must · **Est:** 3h
> **Why this matters:** Finding the first job is a project of its own — with a pipeline, iterations,
> and plenty of rejections. A steady, organized approach and a few real connections beat sending
> hundreds of untailored applications.

## Learning Objectives
- Find and prioritize relevant junior openings.
- Use networking and referrals, not only job boards.
- Run the search as a tracked, iterative process.

## Learn
- [ ] Find a local community: [Java User Groups](https://dev.java/community/jugs/) (dev.java) or
      [Java user groups on Meetup](https://www.meetup.com/topics/java-user-group/).
- [ ] Read:
      [Tech Interview Handbook — Negotiation](https://www.techinterviewhandbook.org/negotiation/)
      (before your first offer arrives).

## Concepts
- [ ] Channels: job boards and LinkedIn, company career pages, internships and trainee programs,
      local meetups and Java User Groups. Referrals convert far better than cold applications.
- [ ] Adjacent entry points exist: QA automation in Java, support or integration engineering,
      internal moves at your current company.
- [ ] Track every application (company, date, contact, stage, next step) in a spreadsheet; follow up
      after a week.
- [ ] Rejections are normal and rarely personal: ask for feedback, adjust your CV or prep, keep a
      weekly rhythm.
- [ ] Judge a first job by how much you'll learn: mentoring, code reviews, tests, CI — not only
      salary.

## Practice
**Goal:** A search you run like a project.
**Steps:**
- [ ] Analyze 20 junior Java job ads: list recurring requirements and close your top gaps.
- [ ] Set a weekly target (e.g. 5 tailored applications + 1 community event or networking chat).
- [ ] Create your application tracker and review it every week.
- [ ] Prepare questions to evaluate a team (code review, onboarding, mentoring).

## Self-check
Answer out loud or on paper first, then expand to compare.

> [!question]- Why do referrals work so well?
> Someone inside vouches for you, so your application skips the anonymous pile and gets read by a
> person who already has a reason to trust it.

> [!question]- What should you do after a rejection?
> Ask for feedback if possible, note what to improve (CV, project, interview answer), adjust, and
> keep your weekly rhythm going.

> [!question]- What matters most in a first developer job?
> Learning opportunities: mentoring, code reviews, a healthy engineering process (tests, CI), and
> colleagues you can learn from.

## Definition of Done
- [ ] I know the requirements of real junior Java roles and have a plan for my gaps.
- [ ] I have a weekly routine and an application tracker.
- [ ] I've joined at least one developer community.
- [ ] I can answer the Self-check questions without peeking.
