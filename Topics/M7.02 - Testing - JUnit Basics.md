# JUnit Basics

> [!info] Topic
> **Area:** Testing · **Module:** 7 · **Priority:** must · **Est:** 4h
> **Why this matters:** JUnit is the standard Java testing framework. The current major version is
> **JUnit 6**; its Jupiter API is the same one older tutorials call "JUnit 5", so they still apply.
> Writing and running unit tests is an everyday skill you'll use in every project from here on.

## Learning Objectives
- Write and run JUnit tests.
- Use lifecycle methods and assertions.
- Write parameterized tests and exception assertions.

## Learn
- [ ] Read: the [JUnit User Guide](https://docs.junit.org/current/user-guide/) — "Writing Tests"
      (annotations, assertions, display names, parameterized tests).
- [ ] Add JUnit to your Maven project (`junit-jupiter`, `test` scope — or `testImplementation` in
      Gradle with `useJUnitPlatform()`).

## Concepts
- [ ] `@Test` marks a test; the **Arrange–Act–Assert** structure keeps tests readable.
- [ ] Lifecycle: `@BeforeEach`/`@AfterEach` (around every test), `@BeforeAll`/`@AfterAll` (once per
      class).
- [ ] Assertions: `assertEquals`, `assertTrue`, `assertThrows` (returns the exception for further
      checks), `assertAll`.
- [ ] `@ParameterizedTest` with `@ValueSource` or `@CsvSource` runs one test over many inputs;
      `@DisplayName` and `@Nested` keep reports readable.
- [ ] Imports are `org.junit.jupiter.api.*`. JUnit 4 (`org.junit.Test`, `@Before`) is legacy —
      mixing the two makes tests silently not run.
- [ ] Name tests for behavior (`returnsZeroForEmptyList`) and test one behavior per test.

## Practice
**Goal:** Test real logic with JUnit.
**Steps:**
- [ ] Write a `Calculator` and test `add`/`divide`, including the divide-by-zero case with
      `assertThrows`.
- [ ] Add a `@ParameterizedTest` with `@CsvSource` covering several input pairs.
- [ ] Group related tests with `@Nested` and give them `@DisplayName`s.
- [ ] Run the tests from the IDE and from the command line (`./mvnw test` / `./gradlew test`).

## Self-check
Answer out loud or on paper first, then expand to compare.

> [!question]- What's the Arrange–Act–Assert pattern?
> Set up the inputs and objects (arrange), call the code under test (act), then check the result
> (assert) — one clear block each.

> [!question]- `@BeforeEach` vs `@BeforeAll`?
> `@BeforeEach` runs before every test method (fresh state each time); `@BeforeAll` runs once before
> all tests in the class (static by default).

> [!question]- Your test class imports `org.junit.Test` and the tests don't run. Why?
> That's the JUnit 4 annotation; the JUnit Platform with Jupiter doesn't pick it up. Use
> `org.junit.jupiter.api.Test`.

> [!question]- How do you assert that code throws an exception with a specific message?
> `var ex = assertThrows(IllegalArgumentException.class, () -> calc.divide(1, 0)); assertEquals("…", ex.getMessage());`
