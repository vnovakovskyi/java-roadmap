# Maven (Project, Dependencies, Lifecycle)

> [!info] Topic
> **Area:** Tooling · **Module:** 6 · **Priority:** must · **Est:** 4h
> **Why this matters:** Maven is the most common Java build tool in the enterprise. It compiles,
> tests, packages, and pulls in libraries — and most Spring Boot examples in this roadmap use it.

## Learning Objectives
- Create and understand a Maven project (`pom.xml`).
- Add dependencies and run the build lifecycle.
- Use the Maven wrapper.

## Learn
- [ ] Do:
      [Maven in 5 Minutes](https://maven.apache.org/guides/getting-started/maven-in-five-minutes.html).
- [ ] Read:
      [Introduction to the Build Lifecycle](https://maven.apache.org/guides/introduction/introduction-to-the-lifecycle.html)
      and the scopes part of
      [Introduction to the Dependency Mechanism](https://maven.apache.org/guides/introduction/introduction-to-dependency-mechanism.html).
- [ ] Read: [Maven Wrapper](https://maven.apache.org/wrapper/).

## Concepts
- [ ] `pom.xml` declares coordinates (`groupId:artifactId:version`), dependencies, plugins, and the
      Java version (`<maven.compiler.release>25</maven.compiler.release>`).
- [ ] Standard layout: `src/main/java`, `src/test/java`, `src/main/resources` (see
      [[M4.09 - Java APIs - Packages and Project Organization]]).
- [ ] **Lifecycle phases**: `validate → compile → test → package → verify → install → deploy`.
      Running a phase runs all earlier ones; `clean` deletes `target/`. CI usually runs `verify`.
- [ ] Dependencies download from Maven Central into your local `~/.m2` cache; **scopes** (`compile`,
      `test`, `runtime`, `provided`) control where they apply.
- [ ] The **wrapper** (`mvnw`) pins the Maven version per project — always use it. (This roadmap
      uses Maven 3.9; Maven 4 is still a release candidate.)

## Practice
**Goal:** Build a real Maven project.
**Steps:**
- [ ] Generate a project (IDE "New Project → Maven", or the archetype from the guide) and set the
      release to 25.
- [ ] Add the wrapper (`mvn wrapper:wrapper`) and use `./mvnw` from now on.
- [ ] Add a dependency (e.g. AssertJ in `test` scope) and confirm it downloads.
- [ ] Run `./mvnw compile`, `./mvnw test`, and `./mvnw package`; find the built `.jar` in `target/`.

## Self-check
Answer out loud or on paper first, then expand to compare.

> [!question]- What does `mvn package` actually run?
> Every phase up to and including `package`: validate, compile, test, then package — so tests run
> first and a failing test stops the build.

> [!question]- What do the `compile` and `test` scopes mean?
> `compile` (default): available everywhere and shipped with the app. `test`: only for compiling and
> running tests (JUnit, AssertJ), never in the final artifact.

> [!question]- Why commit the Maven wrapper?
> So everyone — teammates, CI servers — builds with the same Maven version without installing it.

> [!question]- What are a dependency's coordinates?
> `groupId:artifactId:version`, e.g. `org.assertj:assertj-core:3.27.0` — they uniquely identify it
> in a repository.

## Definition of Done
- [ ] I can read and edit a `pom.xml` and add dependencies.
- [ ] I can run the common lifecycle phases and explain them.
- [ ] I build with `./mvnw` and can find the artifact.
- [ ] I can answer the Self-check questions without peeking.
