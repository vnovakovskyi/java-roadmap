# Module Project (Testing the Bookshelf)

> [!info] Topic
> **Area:** Testing · **Module:** 7 · **Priority:** must · **Est:** 4h
> **Why this matters:** Version 6 puts a safety net under Bookshelf. With tests running in CI, every
> future change — the database in Module 8, any refactoring — is checked automatically. You'll
> probably find a bug or two along the way; that's the point.

## Learning Objectives
- Write unit tests for an existing codebase.
- Use mocks, fakes, and temporary files where they fit.
- Make the build fail when behavior breaks.

## Learn
- [ ] Revisit [[M7.02 - Testing - JUnit Basics]], [[M7.03 - Testing - Assertions with AssertJ]], and
      [[M7.04 - Testing - Mockito and Test Doubles]].
- [ ] Read: JUnit's `@TempDir` in the [JUnit User Guide](https://docs.junit.org/current/user-guide/)
      (search for "TempDir").

## Concepts
- [ ] Unit tests for `Book` validation (`assertThatThrownBy`), the storage, the stats pipelines, and
      command parsing (`@ParameterizedTest` over many inputs).
- [ ] JSON persistence tested with `@TempDir` — a real temporary folder, cleaned up automatically.
- [ ] A mocked or fake `BookStorage` when testing the command handling.
- [ ] "Finished this year" stats tested with an injected `Clock`.
- [ ] CI already runs `./mvnw verify`, so tests now gate every pull request. Optional: a JaCoCo
      coverage report — treat coverage as a hint, not a goal.

## Practice
**Goal:** Bookshelf v6 — a meaningful test suite that runs on every PR.
**Steps:**
- [ ] Write tests for validation, storage, stats, and command parsing.
- [ ] Test saving and loading with `@TempDir`, including a corrupted file.
- [ ] Inject a `Clock` into the stats code and test the year boundary.
- [ ] Open a PR that breaks a test on purpose and watch CI block it; then fix it.
- [ ] Commit, push, and tag `v6`.

## Self-check
Answer out loud or on paper first, then expand to compare.

> [!question]- What did you mock in this project, and what did you deliberately not mock?
> Mock or fake the storage boundary when testing command handling; don't mock `Book` or other simple
> values — use real ones.

> [!question]- Why use `@TempDir` instead of writing to a fixed path?
> Each test gets an isolated, empty folder that's cleaned up afterwards, so tests don't interfere
> with each other or leave files behind.

> [!question]- Your tests pass, and coverage is 95%. Does that mean the app is correct?
> No — coverage only shows which lines ran, not whether the assertions were meaningful or the right
> cases were tested.

## Definition of Done
- [ ] Bookshelf has unit tests for its core logic, persistence, and parsing.
- [ ] Tests run in CI and block broken PRs.
- [ ] The code is tagged `v6`.
- [ ] I can answer the Self-check questions without peeking.
