# Dependency Management and Semantic Versioning

> [!info] Topic
> **Area:** Tooling · **Module:** 6 · **Priority:** good · **Est:** 2h
> **Why this matters:** Real apps stand on dozens of libraries. Understanding versions, transitive
> dependencies, and conflicts saves you from "works on my machine" and mysterious runtime errors —
> and keeping dependencies patched is a security duty.

## Learning Objectives
- Read and reason about version numbers (semver).
- Understand transitive dependencies and conflicts.
- Find, pick, and update library versions responsibly.

## Learn
- [ ] Read: [semver.org](https://semver.org) (it's short).
- [ ] Read: "Transitive Dependencies" in
      [Maven's dependency mechanism](https://maven.apache.org/guides/introduction/introduction-to-dependency-mechanism.html),
      or Gradle's
      [Dependency Resolution](https://docs.gradle.org/current/userguide/dependency_resolution.html).
- [ ] Browse: [Maven Central](https://central.sonatype.com/) — search a library and read its version
      history.

## Concepts
- [ ] **Semantic versioning** `MAJOR.MINOR.PATCH`: major = breaking changes, minor = new features,
      patch = fixes. `-SNAPSHOT`, `-M1`, `-RC1` are pre-releases.
- [ ] **Transitive dependencies**: your libraries' dependencies become yours too.
- [ ] Conflicts: two libraries want different versions of the same dependency; the build tool picks
      one (Maven: "nearest wins", Gradle: "highest wins") — inspect with `./mvnw dependency:tree` /
      `./gradlew dependencies`.
- [ ] A **BOM** (bill of materials — Spring Boot's is the famous one) aligns a whole set of versions
      for you.
- [ ] Security: vulnerable dependencies (CVEs) are a top attack vector. Bots like Dependabot or
      Renovate open upgrade PRs; CI tells you if they break anything.
- [ ] Don't blindly upgrade majors; read the changelog or migration guide first.

## Practice
**Goal:** Inspect and tame the dependency graph.
**Steps:**
- [ ] Print the dependency tree of a project and find a transitive dependency.
- [ ] Force a version conflict (two libraries needing different versions of one dependency) and see
      which version wins.
- [ ] Look up a popular library on Maven Central and read its version history and release notes.
- [ ] Enable
      [Dependabot version updates](https://docs.github.com/en/code-security/tutorials/secure-your-dependencies/dependabot-quickstart)
      on one of your GitHub repositories.

## Self-check
Answer out loud or on paper first, then expand to compare.

> [!question]- A library goes from 2.4.1 to 3.0.0. What does that signal?
> A major version: expect breaking API changes. Read the migration notes and run your tests before
> upgrading.

> [!question]- What is a transitive dependency?
> A dependency of one of your dependencies. You get it automatically — and can be affected by its
> bugs, conflicts, and vulnerabilities.

> [!question]- What does a BOM do?
> It declares a consistent set of versions for related libraries, so you can add them without
> specifying versions and they're known to work together.

## Definition of Done
- [ ] I can interpret semver and decide if an upgrade is risky.
- [ ] I can read a dependency tree and find which version wins a conflict.
- [ ] I understand transitive dependencies, BOMs, and automated update PRs.
- [ ] I can answer the Self-check questions without peeking.
