# Gradle (Project, Dependencies, Tasks)

> [!info] Topic
> **Area:** Tooling · **Module:** 6 · **Priority:** good · **Est:** 4h
> **Why this matters:** Gradle is the other major build tool — concise, fast, and common in newer
> projects and Android. You'll meet both in real jobs: learn one deeply (Maven in this roadmap's
> examples) and be comfortable reading the other.

## Learning Objectives
- Create and understand a Gradle project (`build.gradle.kts`).
- Add dependencies and run tasks.
- Map Gradle concepts to Maven.

## Learn
- [ ] Do:
      [Gradle tutorial, part 1: "Initializing the Project"](https://docs.gradle.org/current/userguide/part1_gradle_init.html)
      (and continue if you like it).
- [ ] Read:
      [Building Java Projects](https://docs.gradle.org/current/userguide/building_java_projects.html)
      and [Version Catalogs](https://docs.gradle.org/current/userguide/version_catalogs.html).
- [ ] Read: [The Gradle Wrapper](https://docs.gradle.org/current/userguide/gradle_wrapper.html).

## Concepts
- [ ] `build.gradle.kts` (Kotlin DSL — the default for new projects) or `build.gradle` (Groovy)
      declares plugins, `repositories`, `dependencies`, and the Java toolchain
      (`languageVersion = JavaLanguageVersion.of(25)`).
- [ ] `gradle init` also creates a **version catalog** (`gradle/libs.versions.toml`) that keeps
      library versions in one place.
- [ ] Dependency configurations: `implementation`, `api` (libraries only), `testImplementation` —
      roughly Maven's scopes.
- [ ] **Tasks** are the unit of work (`build`, `test`, `run`, `jar`); Gradle caches and runs them
      incrementally — usually faster than Maven.
- [ ] The **wrapper** (`./gradlew`) pins the Gradle version per project — always use it.
- [ ] Mental map: `build.gradle.kts` ≈ `pom.xml`, tasks ≈ lifecycle phases, `./gradlew build` ≈
      `./mvnw verify`.

## Practice
**Goal:** Build the same kind of project with Gradle.
**Steps:**
- [ ] Create a Gradle project (`gradle init` or the IDE) with a Java 25 toolchain.
- [ ] Add a `testImplementation` dependency through the version catalog and confirm it resolves.
- [ ] Run `./gradlew build` and `./gradlew test`; locate the artifact in `build/libs`.
- [ ] Note one thing you preferred vs Maven and one you didn't.

## Self-check
Answer out loud or on paper first, then expand to compare.

> [!question]- `implementation` vs `testImplementation`?
> `implementation`: needed to compile and run the main code. `testImplementation`: only on the test
> classpath.

> [!question]- What is `gradle/libs.versions.toml` for?
> It's the version catalog: one place to declare library coordinates and versions, referenced from
> build files as `libs.…` — upgrades become one-line changes.

> [!question]- `gradle` vs `./gradlew`?
> `gradle` is whatever version you installed globally; `./gradlew` uses the version pinned by the
> project, downloading it if needed. Use the wrapper.

## Definition of Done
- [ ] I can read and edit a `build.gradle.kts` and add dependencies.
- [ ] I can run Gradle tasks with `./gradlew`.
- [ ] I can map Gradle concepts to their Maven equivalents.
- [ ] I can answer the Self-check questions without peeking.
