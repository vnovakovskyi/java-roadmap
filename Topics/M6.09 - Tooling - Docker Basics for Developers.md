# Docker Basics for Developers

> [!info] Topic
> **Area:** Tooling · **Module:** 6 · **Priority:** must · **Est:** 4h
> **Why this matters:** Docker runs software — a PostgreSQL database, a message broker, your own app
> — in an isolated container with one command, the same way on every machine. You'll use it from
> Module 8 on to run databases, in tests via Testcontainers, and to ship your capstone.

> [!tip] Install first
> Install Docker Desktop (macOS/Windows) or Docker Engine (Linux) — see **[[Tools & Setup]]**,
> section 5. Podman is a compatible alternative.

## Learning Objectives
- Explain images, containers, ports, and volumes.
- Run and manage containers from the command line.
- Start a multi-container setup with Docker Compose.

## Learn
- [ ] Read: [What is Docker?](https://docs.docker.com/get-started/docker-overview/) (Docker docs
      overview).
- [ ] Do: the first parts of [Docker — Get Started](https://docs.docker.com/get-started/).
- [ ] Do: [Docker Compose — Quickstart](https://docs.docker.com/compose/gettingstarted/).
- [ ] Reference: the official [`postgres` image](https://hub.docker.com/_/postgres) page
      (environment variables, data storage).

## Concepts
- [ ] An **image** is a read-only template (e.g. `postgres:18`, `eclipse-temurin:25-jre`); a
      **container** is a running instance of it. Many containers can run from one image.
- [ ] `docker run -d --name db -e POSTGRES_PASSWORD=secret -p 5432:5432 postgres:18` — detached,
      named, configured by environment variables, port `host:container` published.
- [ ] Everyday commands: `docker ps`, `docker logs db`, `docker exec -it db psql -U postgres`,
      `docker stop db`, `docker rm db`.
- [ ] Containers are disposable: their files vanish with them. Data that must survive goes into a
      **volume** (`-v pgdata:/var/lib/postgresql`).
- [ ] **Docker Compose** describes several containers in `compose.yaml` and starts them together:
      `docker compose up -d`, `docker compose down`.
- [ ] Containers share the host's kernel — they start in seconds and are much lighter than virtual
      machines.

```yaml
# compose.yaml — a local PostgreSQL for development
services:
  db:
    image: postgres:18
    environment:
      POSTGRES_DB: bookshelf
      POSTGRES_USER: bookshelf
      POSTGRES_PASSWORD: bookshelf   # local development only
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql
volumes:
  pgdata:
```

## Practice
**Goal:** Run a real database in a container.
**Steps:**
- [ ] Run `docker run hello-world`, then list containers with `docker ps -a`.
- [ ] Start PostgreSQL in a container, connect with `docker exec -it … psql`, create a table, and
      insert a row.
- [ ] Remove the container and start a new one: the data is gone. Repeat with a named volume: it
      survives.
- [ ] Write the `compose.yaml` above, start it with `docker compose up -d`, check the logs, and stop
      it with `docker compose down`.

## Self-check
Answer out loud or on paper first, then expand to compare.

> [!question]- Image vs container?
> An image is the read-only template; a container is a running (or stopped) instance created from
> it.

> [!question]- What does `-p 5433:5432` mean?
> Port 5433 on your machine is forwarded to port 5432 inside the container — you'd connect to
> `localhost:5433`.

> [!question]- Why does your data disappear when you remove a container, and how do you keep it?
> A container's own filesystem is deleted with it. Store data in a volume, which lives independently
> of any container.

> [!question]- How is a container different from a virtual machine?
> A container shares the host's operating-system kernel and isolates only processes and files, so
> it's small and starts in seconds; a VM runs a whole guest OS.
