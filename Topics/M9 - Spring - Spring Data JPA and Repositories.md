# Spring Data JPA and Repositories

> [!info] Topic
> **Area:** Spring · **Module:** 9 · **Priority:** must · **Est:** 4h
> **Why this matters:** Spring Data JPA removes nearly all boilerplate persistence code — you
> declare an interface and get CRUD, queries, and pagination for free. It's how most Spring apps
> talk to a database.

## Learning Objectives
- Define entities and `JpaRepository` interfaces.
- Use derived query methods, custom queries, and pagination.
- Wire persistence into the service layer.

## Learn
- [ ] Do: the
      [Spring "Accessing Data with JPA" guide](https://spring.io/guides/gs/accessing-data-jpa/).
- [ ] Read:
      [Spring Data JPA — Defining Query Methods](https://docs.spring.io/spring-data/jpa/reference/repositories/query-methods-details.html)
      (including paging and sorting parameters).

## Concepts
- [ ] Map entities with JPA annotations (recap [[M8 - Databases - ORM Intro (JPA and Hibernate)]]).
- [ ] `interface BookRepository extends JpaRepository<Book, Long>` gives `save`, `findById`,
      `findAll`, `deleteById`, and more automatically.
- [ ] **Derived queries** from method names: `findByAuthor(String author)`,
      `findByTitleContainingIgnoreCase(String part)`.
- [ ] `@Query` (JPQL or native SQL) when names get awkward — and for `join fetch` to avoid N+1.
- [ ] **Pagination**: accept a `Pageable` and return `Page<T>`; a controller can bind
      `?page=0&size=20&sort=title` straight into a `Pageable`.
- [ ] Configure: log SQL (`logging.level.org.hibernate.SQL=debug`), set
      `spring.jpa.open-in-view=false` (Spring Boot warns about the default), and use
      `ddl-auto=validate` once Flyway owns the schema.

## Practice
**Goal:** Persist the CRUD app for real.
**Steps:**
- [ ] Replace the in-memory map with a `JpaRepository` backed by PostgreSQL (in Docker).
- [ ] Add a derived query (e.g. `findByAuthorIgnoreCase`) and use it from the service.
- [ ] Make the list endpoint paginated and sortable.
- [ ] Turn on SQL logging and confirm the queries are what you expect.

## Self-check
Answer out loud or on paper first, then expand to compare.

> [!question]- What do you get by extending `JpaRepository<Book, Long>`?
> A ready-made implementation of CRUD operations (`save`, `findById`, `findAll`, `delete…`), plus
> paging and sorting — generated by Spring Data at startup.

> [!question]- How does `findByTitleContainingIgnoreCase` work without an implementation?
> Spring Data parses the method name into a query (`WHERE lower(title) LIKE lower('%…%')`) when the
> app starts.

> [!question]- How would you serve page 3 of books, 20 per page, sorted by title?
> Accept a `Pageable` (`?page=2&size=20&sort=title`; pages start at 0) and pass it to
> `findAll(pageable)`, returning a `Page<BookDto>`.
