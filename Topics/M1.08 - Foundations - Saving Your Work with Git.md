# Saving Your Work with Git

> [!info] Topic
> **Area:** Foundations · **Module:** 1 · **Priority:** must · **Est:** 3h
> **Why this matters:** Git records every version of your code so you can experiment fearlessly and
> roll back mistakes. Start now, and every practice task from here on lands on GitHub — by the end
> of the roadmap that history is part of your portfolio.

## Learning Objectives
- Create a repository and commit changes.
- Read the history and see what changed.
- Push a repository to GitHub.

## Learn
- [ ] Read: [Pro Git — What is Git?](https://git-scm.com/book/en/v2/Getting-Started-What-is-Git%3F)
      and
      [Recording Changes to the Repository](https://git-scm.com/book/en/v2/Git-Basics-Recording-Changes-to-the-Repository).
- [ ] Do: [GitHub — Hello World](https://docs.github.com/en/get-started/using-github/hello-world)

      — the "Share a project on GitHub" part.

## Concepts
- [ ] A **repository** is your project folder plus its full history (stored in a hidden `.git`
      folder).
- [ ] The loop: change files → `git status` → `git add` (stage) → `git commit -m "message"` (save a
      snapshot) → `git log`.
- [ ] A **commit** is a snapshot with a message. Say what changed and why: "Add input validation to
      the grade calculator".
- [ ] `.gitignore` lists files Git should ignore: compiled `.class` files, `out/`, `target/`,
      `build/`, IDE folders like `.idea/`. Ready-made templates:
      [github/gitignore](https://github.com/github/gitignore).
- [ ] A **remote** (GitHub) is an online copy of the repository; `git push` uploads your commits.
      Easiest first push: the IDE's "Share Project on GitHub", or the
      [GitHub CLI](https://cli.github.com) (`gh repo create`).
- [ ] Branches, merging, and pull requests come in Module 6 — for now, commit straight to `main`.

## Practice
**Goal:** Put all your practice code under version control.
**Steps:**
- [ ] Create a `java-practice` repository (`git init`) for your exercises and add a `.gitignore`.
- [ ] Commit your Module 1 programs with clear messages; view the history with `git log --oneline`.
- [ ] Change a file, inspect the change with `git diff`, and commit again.
- [ ] Push the repository to GitHub and find your commits there.
- [ ] From now on: commit after every Practice section.

## Self-check
Answer out loud or on paper first, then expand to compare.

> [!question]- What's the difference between `git add` and `git commit`?
> `git add` stages changes — it chooses what goes into the next snapshot. `git commit` records the
> staged snapshot permanently in the history.

> [!question]- Why shouldn't `.class` files or `.idea/` be committed?
> They're generated or specific to your machine; they bloat the repository and cause pointless
> conflicts. List them in `.gitignore`.

> [!question]- What does `git push` do?
> Uploads your local commits to the remote repository, such as GitHub.

> [!question]- What makes a good commit message?
> A short summary of what changed, written as a command ("Fix off-by-one in loop"), plus why if it
> isn't obvious.

## Definition of Done
